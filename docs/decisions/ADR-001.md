# ADR-001: Layered Backend Architecture

## Decision
Adopt strict handler -> service -> repository layering in backend API.

## Reason
Separates transport, business logic, and persistence concerns; improves testability and change isolation.

## Alternatives Considered
- Fat handlers with inline DB calls.
- Generic repository-less active record approach.

## Tradeoffs
- More boilerplate and indirection.
- Better long-term maintainability and clearer ownership boundaries.

## Status
Accepted and implemented.
